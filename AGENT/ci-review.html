1. Cache-Key kennt die Cargo-Profile nicht

≈2 min pro Run

Key ist hashFiles('Cargo.lock', 'flake.lock'). Seit codegen-units = 1 im Release-Profil (f324182) passt der Cache nicht mehr zu den Flags: wasm-pack baut in jedem Run alle Release-Abhängigkeiten neu (≈1:40 plus ≈20 s wasm-opt). Der Cache wird nie neu geschrieben, weil der Key schon existiert. Deshalb 4:05 statt 2:20 im Job build.

Fix: hashFiles('Cargo.lock', 'flake.lock', '**/Cargo.toml'). Dann erneuert jede Profil- oder Dependency-Änderung den Cache einmal, danach ist er warm.

2. Flaky e2e: Startdialog nach Reload

rot in 36479803054

fonts.spec.ts:12 lädt neu, drückt Escape und hovert die Schriftliste; der modale <dialog class="start"> fängt den Hover ab. Der Dialog erscheint nur, wenn nach dem Reload kein Dokument gespeichert ist: Das Autosave läuft 1 s nach der letzten Änderung oder im pagehide, und dort ist die IndexedDB-Transaktion beim Entladen nicht sicher abgeschlossen. Das Escape im Test umgeht das und verliert das Rennen, wenn showModal() erst nach dem Tastendruck läuft. Der Fehler dahinter ist ein App-Fehler (siehe Code-Review #3): Wer kurz nach einer Änderung neu lädt, kann sie verlieren.

Fix: put in file.ts ruft nach dem put() transaction.commit() auf, damit der Schreibvorgang vor dem Entladen abgegeben wird. Das Escape in fonts.spec.ts fällt weg, und der Test erwartet wie flows.spec.ts nach dem Reload keinen Startdialog.

3. Weitere Flakes, Timeout nur hochgesetzt

3 von 12 Runs rot

Gesehen: pdf.spec.ts:209 Timeout, layers.spec.ts:26 Screenshot-Timeout, canvas.spec.ts:48. Der Test-Timeout wurde von 30 auf 60 s erhöht (d9c14c2); das behandelt das Symptom. Die Shards dauern jetzt 3:30–4:20 für 149 Tests auf SwiftShader.

Fix: In playwright.config.ts retries: process.env.CI ? 1 : 0 mit reporter github plus list. Ein Retry, der grün wird, erscheint im Report als flaky. So bleibt jeder Flake sichtbar und kann an der Ursache behoben werden wie #2, ohne dass er den Deploy blockiert.
