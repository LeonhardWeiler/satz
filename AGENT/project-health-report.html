1. Open findings

BUG-1medium

Numbers without an upper bound break raster output and pass the preflight

engine/src/doc/mod.rs Props::check, TextProps::check, check_frame; web/src/controls.tsx Field (max = Infinity)

Commands require finite numbers but mostly no maximum: stroke weight, radius, blur, shadow offset, text size, letter spacing, line height, indents, gutter and frame size accept anything up to f32::MAX or f64::MAX. Release-mode probe tests (temporary, removed): a stroke weight of 1e10 pt panics in tiny-skia (alpha_runs.rs:189, unwrap on None) in png and inks; 1e8 still works. In WASM this traps the export worker, so the ink preview of a CMYK document, PNG/JPEG export and the flattening of PDF/X-1a fail with a raw message; render and PDF survive. In debug builds text size 1e40 trips debug_assert “text drawn where it was not set” and blur 1e9 overflows i32 in raster.rs:114. In the browser a width of 99999999999 mm was accepted: the ellipse vanished from the page and the preflight said “No issues. The document is ready for print.”

Give every length a maximum in the check functions (e.g. 20000 mm, the limit the view already has; text size 0.1–5000 pt; stroke and blur ≤ the page diagonal) and pass the same bounds as max to the fields. Add a test with the extremes to a_command_that_fails_leaves_the_document_as_it_was.

BUG-2medium

A failed autosave is lost without a word and not retried

web/src/file.ts autosave → put

put sets last = state() before it writes and neither awaits nor checks files.put. If IndexedDB refuses the write (quota with large images, private mode, a blocked database), the error ends as an unhandled rejection or a silent transaction abort, the version counts as saved, and the next save waits for the next change. The user believes the work is kept until the reload shows an older document. Not reproduced in the browser; read from the code.

Await the transaction (oncomplete/onerror), set last only after success, and on failure call editor.say once with “Autosave failed: …, save the file with Ctrl+S”.

A11Y-1medium

Labels, units and hints in --text-3 stay below WCAG AA

web/src/index.css --text-3 (50 uses), light theme --accent, --bad, --warn

--text-3 is the foreground mixed 50 % into the background. Computed contrast: dark theme 4.0:1 on panels, 3.75:1 on inputs, 3.5:1 on raised rows; light theme 3.0:1. At 11–12 px these need 4.5:1. In the light theme the accent is 2.9:1, errors 3.4:1 and warnings 3.2:1 on the panel.

Raise --text-3 to about 62 % in dark and 68 % in light, and darken the light theme's accent, bad and warn until each reaches 4.5:1; check once with the browser's contrast tool.

PERF-1medium

Each image adjustment encodes the whole image as PNG on the main thread

engine/src/image.rs adjusted, file, encode; web/src/renderer.ts:173 MakeImageFromEncoded

Since 5fff04a the per-pixel map is affine and 3 times faster, but every new brightness/contrast/saturation value still makes a new entry, decodes the source, maps it, encodes a 3.9 MB PNG and lets CanvasKit decode it again. Measured natively on earthrise.jpg (3000×3000): 134–140 ms per step (304 ms on 02.10); in WASM a multiple of that, on the main thread, once per scrubbed value.

Put the 4×5 colour matrix into the display list's image op and draw the original with ColorFilter.MakeMatrix; only PDF, plates and inks bake pixels, and they already run in the worker.

BUG-3low

A trap while restoring the autosave goes on with a broken engine

web/src/main.tsx restore catch

The catch around editor.load treats every error alike: keep, download, start a new document. A WebAssembly.RuntimeError leaves the engine in an undefined state (wasm-bindgen borrow flags, half-applied state), and the trap handler is only installed after the render, so the user works on in an engine that may fail later.

In the catch, after keeping and downloading, show the “Satz stopped” notice when e instanceof WebAssembly.RuntimeError; the reload then starts clean because the autosave was moved to doc-unreadable.

BUG-4low

A new service worker deletes the cache an open tab still needs

web/sw.js; web/src/file.ts new Worker(new URL('./exportWorker.ts', …))

install calls skipWaiting, activate deletes every other cache and claims the clients. A tab opened before a deploy creates its export worker only on the first preflight or export, under the old hashed name; that file is no longer in any cache nor on GitHub Pages, so preflight and export fail until a reload. Read from the code, not reproduced.

Drop skipWaiting and clients.claim so the new version takes over on the next load, or keep the previous cache until no client uses it.

BUG-5low

A second job on the same worker takes over the first one's answer

web/src/file.ts run

run assigns w.onmessage and w.onerror per call. If a call starts before the last one answered (preflight closed and opened again during a preview, so the new effect is not busy), the first answer resolves the second promise and the first promise never settles. The effect is a stale ink preview until the next change.

Queue jobs per worker (chain on the previous promise) or tag each message with an id and resolve by id.

UX-1low

Ctrl+Shift+K and Ctrl+Shift+E are not checked in Firefox

web/src/commands.ts ACTIONS

Ctrl+Shift+K (place image) and Ctrl+Shift+E (export) open the web console and the network monitor in Firefox, and Ctrl+Shift+S (save as) takes a screenshot there. Not tested in Firefox; Playwright presses keys inside the page and cannot see this.

Check them once by hand in Firefox and move any that the browser keeps.

UX-2low

PNG or JPEG export of several pages starts one download per page

web/src/App.tsx exportAs; web/src/file.ts download

An 8-page booklet as PNG triggers 8 downloads in a row; Chromium asks whether the site may download multiple files, and a denied prompt drops all but the first without a message in Satz.

Bundle more than one page into a zip, as the package export already does.

PERF-2low

Images are decoded again after a spread change

web/src/renderer.ts:272–276

The renderer deletes every CanvasKit image not drawn in the current frame, so switching spreads or scrolling an image out of view decodes it again (a 3000×3000 JPEG noticeably; not measured alone). The pruning exists for the intermediate images of PERF-1.

After PERF-1, keep the images of the document and free only those whose hash left it.

PERF-3low

A keystroke sets its whole story again and rebuilds the whole snapshot

engine/src/doc/story.rs flow; engine/src/doc/draw.rs snapshot; web/src/editor.ts change

Native benchmark, release, fast runs: keystroke 0.67 / 5.4 / 16 ms at 1 / 8 / 32 pages (14.1 ms on 02.10), set_frame 9.6 ms at 32 pages, render 0.03 ms. Every command also serialises the full snapshot to JSON and the UI parses it again, on every drag move too. Browser cost not measured.

Measure in the browser first. Set a story again only from the frame that changed, and send only changed pages of the snapshot if the measurement shows it.

PERF-4low

Unicode character names cost 277 kB gzip at every start

engine/Cargo.toml unicode_names2; engine/src/text.rs:119 characters

The engine WASM grew from 2.81 to 3.40 MB gzip since 02.10. A build without unicode_names2 (temporary worktree) is 3,041,505 instead of 3,318,372 bytes gzip after wasm-opt: 8 % of the engine for the search by name in the characters panel, which few sessions open.

Search by code point and block only, or fetch a names file when the panel opens.

SEC-1info

No content security policy

web/index.html

GitHub Pages sends no security headers and the page sets no CSP meta tag. Risk is small: no backend, user files are parsed by Rust and CanvasKit, no user HTML is rendered.

Add <meta http-equiv="Content-Security-Policy"> with default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline' and run the e2e suite against it.

It has no assertions, waits with fixed timeouts and prints page lines, so the local run counts 216 tests against 215 in CI and adds noise.

Keep it outside web/e2e or behind an environment variable.
