1. Open findings

BUG-1high

Gradient shader leaks into page, guides and handles

web/src/renderer.ts (TODO B1, bugs.md 1, 2, 13, 14)

One shared Paint draws content, the white page, trim/bleed guides and the selection overlay. drawOp deletes the gradient shader while it is still attached; the chrome code only calls setColor, so after re-recording a gradient item the page, guides and handles are drawn with the deleted shader. Canvas only; the PDF is correct.

Separate paint for chrome, setShader(null) before shader.delete(), and an e2e that moves a gradient item and samples page-white and handle-blue pixels.

BUG-2medium

Lines and arrows are resized as boxes

web/src/Canvas.tsx handleAt (TODO B2)

With h = 0 the n and s edge zones cover the whole line, so a press resizes instead of moving; corner handles scale both axes.

Endpoint handles for two-point paths written through setPath; no edge handles on a zero axis.

BUG-3medium

A mask hides more than expected and is invisible in the layers panel

engine/src/doc.rs draw_all, hit; web/src/Layers.tsx (TODO B4)

A mask masks every later sibling in its parent, so a page-level frame used as mask hides the whole page. The layers panel shows nothing, and hit ignores masks, so hidden parts stay clickable.

Figma "Mask group" on multi-selection, mask icon and scope in the layers panel, hit test against the mask outline.

BUG-4medium

Undo while a pen path or drag is open

web/src/keys.ts (TODO B9)

Ctrl+Z inside the open pen undo group can remove the path node; the next setPath throws. Undo during a drag mixes with the drag's undo group.

Finish the pen before undo/redo; ignore undo/redo while a drag is active.

BUG-5medium

Dropping a layer into its own descendant throws

web/src/Layers.tsx over, onDrop; engine/src/doc.rs Command::Move

over only rejects the dragged rows themselves. Dragging an expanded group onto one of its children (into, above or below) sends a move whose target parent is inside the moved node; Loro rejects the cyclic move, the JsError escapes the drop handler and the drop indicator stays visible.

Reject targets inside a dragged subtree in over, and check ancestry in Command::Move before the first mov_to.

BUG-6medium

Text content box is stale after undo and re-applies the undone text

web/src/Properties.tsx (Text section textarea)

The textarea is uncontrolled with key={one.id}. After Ctrl+Z restores an older text, the box still shows the newer one; focusing and leaving it compares against the restored text and sends setText again, silently redoing the edit.

Key the textarea on id and text, or keep a draft like Field does.

ROB-1medium

Commands are not atomic and engine errors are unhandled

engine/src/doc.rs apply; web/src/editor.ts apply; web/src/Properties.tsx each

apply returns Err after partial mutation (e.g. Move, Group loop over several ids) and skips commit, so the half-done ops land in the next command's transaction. In the UI a throw inside beginUndoGroup … endUndoGroup (property edits, drags, nudges) leaves the group open, so later edits merge into one undo step. The snapshot is not refreshed after the error.

Validate all inputs before the first mutation in each command; have Editor.apply end an open undo group and re-read the snapshot on error.

PERF-1medium

Full snapshot and full text layout on every event

engine/src/doc.rs render, hit; web/src/editor.ts; web/src/Canvas.tsx

Each drag step serialises the whole document to JS (Editor.apply), rebuilds it again for the display list and reshapes and re-breaks every text item (harfrust + Knuth-Plass) per frame. Every hover pointermove calls hit, which builds another full snapshot. Fine for the demo page; it will not hold for the 8-page booklet with threaded text.

Cache text layout per node keyed by text, size and frame; render and hit test from one cached tree that commands invalidate.

PERF-2medium

PDF export blocks the UI; raster size has no upper bound

web/src/App.tsx exportPdf; engine/src/pdf.rs; engine/src/raster.rs

Export runs synchronously on the main thread without feedback. Shadows and blurs are rasterised at the document ppi, which accepts any positive value: an A2-sized shadow at 300 ppi is ≈ 4961 × 7016 px (≈ 139 MB per buffer, several copies during blur and demultiply); a large ppi can exhaust WASM memory and trap the engine.

Cap rasterPpi in SetDocument (part of TODO B6); show progress, later move export into a Worker.

UX-1medium

Blank screen while ≈ 5 MB of WASM load, and on load failure

web/src/main.tsx, web/index.html

Build output: engine_bg.wasm 2.1 MB gzip, canvaskit.wasm 3.0 MB gzip. Nothing is rendered until both are initialised; if the fetch or init fails, the page stays empty with no message. This is the first impression of the live portfolio build.

Static loading text in index.html; catch the init promise and render the same notice style as the WebGL message.

TEST-1medium

E2E misses re-recording, chrome pixels and Firefox

web/e2e/pdf.spec.ts, web/playwright.config.ts

The canvas-vs-PDF check compares content only and never edits a gradient item before comparing, which is why BUG-1 passed CI. Only Chromium runs, although Firefox is a settled target browser.

Add the BUG-1 regression test; add a Firefox project once its WebGL path works in CI.

UX-2low

Hover and cursor ignore modifier keys and keyboard edits

web/src/Canvas.tsx onPointerMove (TODO B5)

Hover always uses pick(…, 'click'), so Ctrl does not preview the deep pick; hover and cursor only update on pointer move, so a resize cursor stays after Delete.

Keep the last pointer position and modifiers; recompute on Ctrl down/up and on every editor change.

UX-3low

No limits or rounding on typed values

web/src/controls.tsx, engine/src/doc.rs set (TODO B6)

The engine accepts any value through Set/SetFrame; the UI clamps a few fields ad hoc (Math.max in Properties).

Limits in the engine only, 2-decimal rounding in Field; drop the UI-side clamps.

UI-1low

Empty fill/stroke/effect lists still render and keep margins; the stroke settings grid sits too close to the list.

A11Y-1low

Layers tree has tree roles but no tree keyboard behaviour

web/src/Layers.tsx

role="tree"/treeitem promise arrow-key navigation, but every row is a separate tab stop and reordering is drag-and-drop only. As the canvas has no keyboard access, the layers panel is the only way to reach objects without a mouse.

Roving tabindex with Up/Down/Left/Right on the tree; the existing [/] shortcuts already cover reordering.

PERF-3low

MEM-1low

Renderer caches never evict

web/src/renderer.ts pictures, font

Pictures of deleted items stay in the map until the canvas unmounts; font() creates a new Typeface per size and never deletes it.

Drop pictures whose item did not appear in the current display list; one typeface per font id.

ARCH-1low

All pointer logic lives in one untested effect

web/src/Canvas.tsx

Handle detection, resize maths, marquee and drawing sit in a single ≈ 380-line useEffect. BUG-2 and UX-2 will grow it, and none of it has unit tests, unlike select.ts and pen.ts.

Move handleAt and the resize computation into a pure module with vitest cases before fixing BUG-2.

SEC-1low

GitHub Actions pinned to tags, not commits

.github/workflows/ci.yml

The deploy job holds pages: write and id-token: write; third-party actions are referenced by mutable major tags.

Pin actions to commit SHAs (Dependabot keeps them current).

UX-5info

Start zoom shows 127 %

web/src/renderer.ts fitView (bugs.md 16, not yet in TODO)

The page is zoomed to fit the window; 127 % is the fit value for the A5 page at that window size. This matches Figma. Shift+0 gives 100 %.

Keep fit; answer bugs.md 16 in the TODO so it is not reported again.

BUG-7info

Text looks heavier in the PDF than on the canvas
