1. Open findings

DATA-1medium

An autosave that cannot be restored is overwritten by the next document

web/src/main.tsx (restore branch); web/src/file.ts autosave

When editor.load rejects the autosaved bytes (a future format change, a Loro upgrade, a stricter Doc::load check), Satz says it started a new document and opens the start dialog. The first change after that, even Esc which opens the booklet, makes autosave put the new document under the same key doc. The unreadable bytes are gone, and for a document never saved to a file they were the only copy.

On a failed restore, move the stored entry to a second key (e.g. doc-unreadable) before anything is autosaved, and offer it as a download in the status message so it can be opened by a later version.

UX-1low

New document is listed as Ctrl N, which the browser keeps for a new window

web/src/commands.ts ACTIONS; web/src/App.tsx onKey

Chromium and Firefox do not pass Ctrl+N to a page in a normal window; it opens a new browser window. Help and the palette list "Ctrl N"; the handler only works because it ignores Alt, so Ctrl+Alt+N (as the UI G inventory specifies) reaches it. Playwright presses keys inside the page and so cannot catch this. Ctrl+Shift+K (place image) and Ctrl+Shift+E (export) open developer tools panels in Firefox; not tested there.

List and bind New document as Ctrl Alt N; check the Ctrl+Shift shortcuts once by hand in Firefox and move any that the browser keeps.

UX-2low

The Pages field in the document section leaves 17 px for its number

web/src/Properties.tsx DocumentSection; web/src/index.css .grid, .field-step

In the half-width grid cell, the label "Pages" and the 2 step buttons of 22 px leave the input 17 × 28 px (Lighthouse target-size, the only accessibility failure, score 97). A 3-digit count is cut off and the input is hard to hit.

Give the Pages field the whole row, or a short label (e.g. an icon) like the other fields of the grid.

UX-3low

An example that does not load gives no feedback

web/src/Start.tsx example

example fetches booklet.satz or poster.satz without a catch. Offline, after a deploy that renamed the hashed asset, or on a 404 page, the fetch or editor.load rejects unhandled: the dialog stays as it is and nothing is said. On the first start Esc takes this path.

Catch the error and show it through say (e.g. "Could not open the booklet: … Create a new document instead."), keeping the dialog open.

ROB-1low

The 50-megapixel limit holds for placing, not for opening a document

engine/src/doc/mod.rs add_image, load; engine/src/image.rs register

MAX_PIXELS is checked in add_image only. Doc::load registers every image of a .satz file through image::register without it, so a document made elsewhere (or by a changed build) with a larger image decodes it on the first draw and stops Satz with the trap notice instead of a message.

Move the size check into image::register, so every way in refuses the image with the same message; load then fails with a clear reason.

ROB-2low

Traps while adding a font or in the export worker look like ordinary errors

web/src/file.ts addFont, findFonts, run; web/src/exportWorker.ts

placeImage and apply rethrow WebAssembly.RuntimeError, addFont does not: a font that panics the parser shows "Could not add …" while the engine is unusable, until the next autosave throws. In the worker, a trap is posted as { error: "unreachable" }; run keeps the broken worker, so every later export and preflight fails with the same word.

Rethrow RuntimeError in addFont like placeImage; in the worker post whether the error was a trap and let run reset the job then, so the next export starts a fresh worker.

PERF-1low

A keystroke sets the same story several times and rebuilds the whole snapshot

engine/src/text.rs set (via lay_out, overflow, lines, caret, measure); engine/src/doc/draw.rs snapshot

Measured today (native, release, median): keystroke 0.59 / 4.79 / 13.95 ms and set_frame 0.26 / 1.96 / 8.23 ms at 1 / 8 / 32 pages. Each caller shapes and breaks the story again, and every command serialises the whole snapshot to JSON. In WASM a keystroke in a 32-page document is over one frame.

Keep the set lines in the flow cache that already lives for one command and let drawing, caret and overlay read them; measure again before caching the snapshot per page.

TEST-1low

E2E runs in Chromium only

web/playwright.config.ts

Firefox is a settled target browser, with its own save path (download instead of the file picker) and no Local Font Access, but only a Chromium (SwiftShader) project runs. UX-1 is the kind of fault this misses.

Add a Firefox project, first for the file, start and webgl specs, once its WebGL path runs in CI.

BUILD-1info

Every build warns that fs and path were externalised for CanvasKit

web/vite.config.ts

canvaskit.js requires Node's fs and path in a branch that never runs in the browser, so vite build prints 2 warnings on every run. The chunk size warning is gone; these 2 still hide a new one.

Filter exactly these 2 messages in the build's onwarn/onLog, so a clean build prints no warning.

SEO-1info

No meta description

web/index.html

Lighthouse (desktop, live Pages build): performance 98, accessibility 97, best practices 100, SEO 90; the SEO point is the missing <meta name="description">. The cache lifetime of 10 min is set by GitHub Pages and the unminified script belongs to browser extensions.

Add a one-line description ("Desktop publishing in the browser …", as in the README).

2. What is already strong

  • gate ./check in nix develop passes end to end on b710603: fmt, clippy -D warnings, 234 cargo tests (plus the ignored benchmark), wasm build, tsc, eslint, 37 vitest tests, build, 155 Playwright tests. E2E fails on console errors and waits for the drawn frame, not a fixed delay. CI runs the same script, e2e in 3 shards with 1 retry that is reported as flaky.
  • test Pixel diff of the live canvas against the exported PDF rasterised by MuPDF, in RGB and CMYK and per page; PDF presets and separations are checked too. The display-list fixture is committed and cargo test fails when it is stale, so Rust and TS check the same file.
  • test Engine tests read as specifications and check undo with stable ids; a_command_that_fails_leaves_the_document_as_it_was guards every command arm. E2E now covers dragging layers, saving into a picked file, opening through the picker and finding fonts through Local Font Access.
  • engine Props, colours, page sizes and document settings are range-checked before the first mutation; turned layers are measured where they show for preflight and snaps; a trap stops autosave and shows a reload notice.
  • design One display list feeds canvas and PDF; the PDF and preflight rasters are made in a worker; line breaking is linear per paragraph; equal effect groups are rasterised once per export.
  • build Toolchain fully in flake.nix; wasm-bindgen pinned to the CLI version in the flake; 3 runtime web dependencies; actions pinned to commits and kept current by Dependabot; CI with contents: read by default and skipped for agent-only pushes; CLAUDE.md matches the code.
  • a11y Labelled controls, :focus-visible styles, menu and radio roles, combobox selects, role="tooltip"; layers and pages lists are one tab stop each with arrow keys; loading, WebGL 2, start-failure and trap notices, each with an e2e test.

3. Deliberately decided

RenderingCanvasKit (Skia, WebGL2) drawing a binary display list; replaced Vello for GPU effects. Large WASM download accepted.

FontsA font library per browser in IndexedDB, not in the document or .satz; text refers to a font by name and hash. A missing font falls back to the bundled Source Serif 4 and is pink on the canvas only. TTF and OTF, picked in the text section.
