1. Open findings

PERF-1high

Threaded text is laid out many times per event, growing with frames × story

engine/src/doc.rs flows, flow, holding, prev_of, snapshot, render, master_layers, hit; engine/src/text.rs rows; web/src/editor.ts follow

flow calls text::overflow per frame, and rows shapes and breaks the whole rest of the story each time, not just what fits. snapshot runs flows over every story, render builds a full snapshot and master_layers runs flows again, hit builds another snapshot on every hover, caret/textLine run flow twice, textOverlay once per frame, and Editor.follow calls textFrame after every apply and set. Each text node in the snapshot carries a copy of the whole story and its spans. prev_of walks every node of the document per call.

Measured in Node on the built WASM, one fixed A5 text frame per page, threaded (the same shape as the M1 booklet):

1 page, 5 k chars4 pages, 20 k8 pages, 41 k
snapshot9 ms75 ms255 ms (342 kB JSON)
displayList13 ms116 ms289 ms
hit7 ms117 ms250 ms
caret / textOverlay16 ms≈ 320 ms≈ 536 ms
pdf156 ms762 ms2 658 ms

A typed character triggers snapshot, display list, caret, overlay and textFrame: well over 1.5 s on 8 pages. The M1 booklet is not editable at this speed.

Compute the flows once per command in finish and keep them on Doc; render, hit, caret and the overlay read that cache. Stop rows at the frame's capacity so each frame shapes only its own lines. Put the story text and spans once per story into the snapshot; frames carry start/end. Add an engine test that builds the 8-page threaded booklet and asserts a time budget for apply + render + caret, so the regression shows in ./check.

BUG-10high

A trailing space wraps auto-width text onto a new line

engine/src/text.rs rows (natural), measure; engine/src/linebreak.rs break_lines

Typing in a text with auto width: after a space the caret jumps to a new line as if Enter was pressed; the next letter brings it back. natural still sums items only up to the last Box, so the hugged width leaves out the trailing space, while break_lines counts that Glue on the last line: "Hello␣" is one space wider than the frame, the breaker breaks at the glue and adds an empty line. The frame grows by one line until the next letter.

Sum natural over all items of the paragraph instead of up to the last Box. Add a measure test with "Hello " expecting one line and an e2e test typing a space in an auto-width text.

BUG-12medium

Duplicating a page or several threaded frames breaks the thread and repeats the story

engine/src/doc.rs clip, paste, Command::DuplicatePage, Command::Duplicate

clip gives every frame of a thread the whole story, and paste drops next. Duplicating a page whose frames a → b are threaded yields two unthreaded copies that each start at the beginning of the story, so the new page shows the same opening twice and both are overset. The same happens for Ctrl+D on both frames. The engine test a_copy_of_a_threaded_frame_holds_its_whole_story_and_no_thread covers only one copied frame; InDesign keeps the thread between copied frames.

When a command copies several frames of one thread, give the story to the first copy only and relink next among the copies (map old id → new id after pasting). Add engine tests for DuplicatePage and Duplicate with a thread inside the copied set.

TEST-3medium

Tests use tiny documents and miss combinations of pages, masters and threads

engine/src/doc.rs tests; engine/src/text.rs tests; web/e2e/thread.spec.ts, masters.spec.ts, pages.spec.ts

Engine thread tests use stories like "Hi\nHi\nHi\nHi" in 2–3 frames; the e2e story has 230 characters. No test builds anything near the M1 booklet, which is why PERF-1 went unnoticed through 5 feature commits. Each feature is tested alone: nothing duplicates a page with a thread (BUG-12), threads between a master and a page (BUG-13), deletes a page or master holding a thread head, or gives threaded frames different modes (BUG-14). Engine modules layout.rs, style.rs and variable.rs have no tests of their own and are covered only through doc.rs.

Add one fixture that builds the 8-page A5 booklet (master with page number area, one story threaded through all pages, a variable mode per page) and reuse it for a timing test (PERF-1), a PDF text-extraction check and the cross-feature cases above. The M1 example booklet (TODO item 16) can become this fixture.

TEST-2medium

E2E tests time out at random under full load

web/e2e/util.ts pixels; web/e2e/variables.spec.ts; web/e2e/pdf.spec.ts expectCanvasMatchesPdf; web/playwright.config.ts

./check passed 52 of 52 in this review. A second run with --repeat-each=2 failed 2 of 104: "a fill bound to a colour variable follows the mode of its frame and page" (selectOption) and "draw shapes and a closed pen path, then export them" (page.screenshot), both at the 30 s timeout. 8 workers share SwiftShader; pixels, the PDF comparison and the variables test wait a fixed 100 ms instead of for a drawn frame. pixels is now also used by the thread and master tests. A flaky gate fails CI deploys at random.

Expose a frame counter on the canvas (e.g. data-frame) and wait for it to change instead of waitForTimeout; limit workers in CI (workers: process.env.CI ? 2 : undefined).

BUG-11medium

Rectangles, ellipses, frames and text boxes can be set to width or height 0

engine/src/doc.rs resize; web/src/Canvas.tsx handleAt, resize and draw drags; web/src/Properties.tsx

resize only rejects negative sizes. Typing 0 into H, dragging a handle onto the opposite edge, or a purely horizontal draw drag gives a box of height 0: invisible, a frame clips all children away, handleAt hides the n/s handles, and group resize uses the scale fallback 1. Only the H field brings it back. A fixed text frame of height 0 in a thread pushes its whole share on to the next frame.

In resize clamp w and h to 0.01 mm for every kind whose bounds are not derived from a path; lines, arrows and pen paths keep 0. Add engine tests for both groups and an e2e test typing 0 into H.

UX-1medium

Blank screen while ≈ 5.7 MB of WASM load, and on load failure

web/src/main.tsx, web/index.html

Build output: engine_bg.wasm 2.7 MB gzip, canvaskit.wasm 3.0 MB gzip. Nothing is rendered until both are initialised; if the fetch or init fails, the top-level await rejects and the page stays empty. This is the first impression of the live portfolio build.

Static loading text in index.html; catch the init promise and render the same notice style as the WebGL message.

BUG-13low

A master frame can thread into a page frame

engine/src/doc.rs Command::Thread

Thread checks kind and existing links, not where the frames live. A master text frame threaded into a frame on page 3 shows the story's opening on every page using that master, and its rest only on page 3; overriding the master frame on a page copies the whole story (BUG-12), and switching page 3 to another master leaves a thread into a layer it no longer shows. InDesign allows threads within masters or within document pages, not between them.

Reject Thread when one frame is on a master and the other is not (compare kind of root(a) and root(b)); add the case to only_fixed_frames_thread_and_the_last_may_be_auto_height.

BUG-14low

Range colours of a threaded or master text use the modes of the first frame

engine/src/doc.rs flow (active_modes(head)), master_layers

flow resolves the story's spans once in the modes of the thread's head. A range coloured with a colour variable keeps the head's mode in later frames on pages with another mode, while the frame's own fill follows the frame. Master texts resolve spans in the master's modes, not the showing page's, although master_layers merges the page's modes for everything else.

Keep sizes resolved once per story (they decide the breaks) and resolve span paints per frame in draw with the frame's scope, as the fills already are.

UX-8low

Threading into an already threaded frame fails silently

web/src/Canvas.tsx onPointerDown (threading branch), onPointerUp

With a loaded out-port, clicking a text frame that already has a previous or next frame makes thread throw; the error goes to console.warn, the threading cursor ends and the frame gets selected as if it had worked. Nothing tells the user why the text did not flow.

Show a not-allowed cursor over frames that cannot take the thread while threading, and keep threading active after a refused click.

PERF-2low

PDF export blocks the UI without feedback

web/src/App.tsx exportPdf; engine/src/lib.rs pdf

Export runs synchronously on the main thread. pdf calls render per page, and each builds a full snapshot of all pages, so the cost grows with pages² (2.7 s for the threaded 8-page booklet, see PERF-1). The tab freezes without any sign of progress.

Render all pages from one snapshot (fixed with PERF-1); show a busy state before the call; later move export into a Worker.

TEST-4low

Long scenario tests with weak or fixed-size assertions

web/e2e/thread.spec.ts, masters.spec.ts, web/e2e/util.ts screen; engine/src/doc.rs threaded_frames_set_one_story_that_flows_on_across_frames_and_pages

The thread e2e test runs ≈ 50 steps (thread by click, by drawing, across pages, caret follow, typing, unthread, undo) and the engine thread test ≈ 25 assertions; the first failure hides everything after it and does not say which feature broke. Some checks prove little: expect(title).not.toHaveText('Text') passes for any other title, overset is only checked to be on and never to go off after threading, the master colour check samples one pixel. screen() hard-codes an A5 page, so tests on resized pages fall back to canvas fractions.

Split the scenarios into one test per behaviour (click, draw, cross-page, caret, unthread) sharing a setup helper; assert positive values (expected title, overset off after threading); let screen() read the current page size from the Properties panel or the snapshot.

TEST-5low

Vitest depends on artefacts written by cargo test and wasm-pack

engine/src/display_list.rs test writing web/src/testdata/; web/src/displayList.test.ts; web/src/renderer.test.ts; .gitignore

A Rust test writes display-list.bin/.json into the gitignored web/src/testdata, which the TS decoder test reads; renderer.test.ts needs the wasm-pack output. ./check runs them in the right order, but pnpm test on a fresh clone fails with a missing file, and a test with a side effect on another package is surprising.

Commit the fixture and let the Rust test compare against it (failing with a hint to regenerate), so both sides check the same file; state in the README that pnpm test needs the wasm build.

UX-7low

A click on a swatch in the Swatches panel does nothing

web/src/Swatches.tsx (onPick={() => {}})

Rows look and announce as selectable options, but a single click neither selects nor applies; editing needs a double-click, which is not discoverable. InDesign applies the swatch to the selection on click.

Click applies the swatch to the selection's fill (or opens the editor when nothing is selected); double-click edits.

A11Y-1low

web/src/Layers.tsx, web/src/Pages.tsx, web/src/ContextMenu.tsx

role="tree"/treeitem in Layers promise arrow-key navigation, but every row is a separate tab stop. Pages reorder by drag only. The context menu has role="menu" but no arrow-key movement between its items.

MEM-1low

web/src/renderer.ts font

font() copies the 262 kB font file into a new Typeface for every distinct size and deletes neither typeface nor unused fonts until unmount.

One typeface per font id; Font objects per size are cheap.

ARCH-1low

PRINT-2info

Blurred and shadowed spot colours print as process

engine/src/pdf.rs raster

Shadows and blurs of CMYK documents become one CMYK image; spot inks are converted through their alternate, so that part of the artwork is missing from the spot plate. Expected for rasterised effects, but the user gets no hint.

Report it in preflight (TODO item 15) next to RGB content in CMYK documents.
