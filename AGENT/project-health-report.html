1. Open findings

BUG-10high

A trailing space wraps auto-width text onto a new line

engine/src/text.rs rows (natural), measure; engine/src/linebreak.rs break_lines

Typing in a text with auto width (hug on both axes): after a space the caret jumps to a new line as if Enter was pressed; the next letter brings it back. natural sums items only up to the last Box, so the hugged width leaves out the trailing space. The space is still a Glue item before FILL/FORCE, and break_lines counts it on the last line: the line "Hello␣" is one space wider than the frame (r = −3, overfull), so the breaker breaks at that glue and adds an empty line holding only the end of the paragraph. The caret after the space sits on that empty line; the frame height grows by one line. With the next letter the space is inside the content again and everything fits on one line.

Let the hugged width include trailing spaces: sum natural over all items of the paragraph instead of up to the last Box. The frame grows with each space and the caret stays on the line, as in Figma. Add a measure test with "Hello " expecting one line, and an e2e test typing a space in an auto-width text.

BUG-11medium

Rectangles, ellipses, frames and text boxes can be set to width or height 0

engine/src/doc.rs resize; web/src/Canvas.tsx handleAt, resize and draw drags; web/src/Properties.tsx frame

resize only rejects negative sizes, for every kind. Typing 0 into H (or W), dragging a handle onto the opposite edge, or drawing a rectangle with a purely horizontal drag gives a box of height 0. Such a box is invisible, a frame clips all its children away, and it cannot be grown back on the canvas: handleAt hides the n/s handles when box.h is 0 (the rule meant for lines), and group/multi-selection resize uses the scale fallback 1 for that axis. Only the H field brings it back. Size 0 only makes sense on the flat axis of lines, arrows and straight pen paths.

Enforce a minimum size in the engine, in one place: in resize clamp w and h to 0.01 mm for every kind whose bounds are not derived from a path (rectangle, ellipse, polygon, star, frame, text, image); lines, arrows and pen paths keep 0. The canvas and the fields then need no rules of their own; the draw drag produces the minimum instead of 0. Add engine tests for both groups and an e2e test typing 0 into H.

TEST-2medium

A variables e2e test times out under full load

web/e2e/variables.spec.ts "a fill bound to a colour variable follows the mode of its frame and page"; web/playwright.config.ts

In this review ./check failed: this test exceeded the 30 s timeout while 44 others passed. Run alone it passed 3 of 3 times in ≈ 7 s. It opens the picker twice, switches modes three times and takes screenshots after a fixed waitForTimeout(100); with all workers on SwiftShader in parallel that is too slow or races the redraw. A flaky gate fails CI deploys at random and teaches to ignore red runs.

Replace the fixed wait with a poll (expect.poll on the sampled colours), split the test into one per mode switch, and limit workers in CI (workers: process.env.CI ? 2 : undefined) if SwiftShader stays the bottleneck.

PERF-1medium

Full snapshot and full text layout on every event

engine/src/doc.rs render, hit; web/src/editor.ts; web/src/Canvas.tsx

Each setFrame of a drag and each typed character while editing text serialises the whole document to JS (once per selected node), render builds it again for the display list and reshapes and re-breaks every text item per frame, and every hover pointermove calls hit, which builds another full snapshot. Engine.pdf builds one snapshot per page. Every command also runs settle and lay_out over the whole tree (noted under Later in TODO). Fine for the demo page; it will not hold for the 8-page booklet with threaded text.

Cache text layout per node keyed by text, size and frame; render and hit test from one cached tree that commands invalidate; one setFrames command for multi-node drags.

UX-1medium

Blank screen while ≈ 5.7 MB of WASM load, and on load failure

web/src/main.tsx, web/index.html

Build output: engine_bg.wasm 2.7 MB gzip (was 2.4; hyphenation patterns and text styles grew it), canvaskit.wasm 3.0 MB gzip. Nothing is rendered until both are initialised; if the fetch or init fails, the top-level await rejects and the page stays empty. This is the first impression of the live portfolio build.

Static loading text in index.html; catch the init promise and render the same notice style as the WebGL message.

TEST-1low

UX-7low

A click on a swatch in the Swatches panel does nothing

web/src/Swatches.tsx (onPick={() => {}})

Rows look and announce as selectable options, but a single click neither selects nor applies; editing needs a double-click, which is not discoverable. InDesign applies the swatch to the selection on click.

Click applies the swatch to the selection's fill (or opens the editor when nothing is selected); double-click edits.

MEM-1low

web/src/renderer.ts font

Item and layer pictures are now evicted. font() still copies the 262 kB font file into a new Typeface for every distinct size and deletes neither typeface nor unused fonts until unmount.

One typeface per font id; Font objects per size are cheap.

ARCH-1low

Handle detection, line ends, resize maths, marquee, drawing and pen sit in a single ≈ 400-line useEffect in a 600-line file. None of it has unit tests, unlike select.ts and pen.ts; only e2e covers it.

Move handleAt and the resize computation into a pure module with vitest cases.

PRINT-2info

Blurred and shadowed spot colours print as process

Shadows and blurs of CMYK documents become one CMYK image; spot inks are converted through their alternate, so that part of the artwork is missing from the spot plate. Expected for rasterised effects, but the user gets no hint.
