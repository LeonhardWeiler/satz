1. Open findings

BUG-1medium

Preflight's trim and bleed check and snapping use the unturned frame of a rotated layer

engine/src/doc/draw.rs visit (insets from n.x, n.w); web/src/snap.ts targets; web/src/Canvas.tsx snapsNow

Rotation is stored beside the frame and applied around its centre, but the preflight measures the distance to trim and bleed from x, y, w, h alone, and so do the snap lines of other layers. A rectangle turned 45° whose corners reach past the trim but stop short of the bleed is not reported as short of bleed, and one whose frame touches the trim while its turned shape stays inside is reported wrongly; layers snap to edges and centres that are not where the rotated layer shows. A layer inside a rotated group has the same problem through its ancestors' transform.

Give the engine one bounding box per node that includes its own and its ancestors' rotation (the transform already exists at doc/mod.rs for drawing and hits), send it in the snapshot, and use it in visit and targets; add a preflight test with a turned rectangle near the trim.

UX-8low

A refused thread ends threading

web/src/Canvas.tsx onPointerDown (threading branch), onPointerUp

With a loaded out-port, clicking a text frame that already has a previous or next frame makes thread throw, as does a frame on a master threaded with one on a page; the reason shows in the status bar, but the threading cursor ends and the frame gets selected as if it had worked; a frame drawn from the port stays behind unthreaded.

Show a not-allowed cursor over frames that cannot take the thread while threading, and keep threading active after a refused click.

ROB-1low

A trap in the engine shows as an ordinary status message

web/src/editor.ts apply; web/src/file.ts autosave

apply catches every error and puts its message in the status bar. A rejected command and a Rust panic or out-of-memory trap (e.g. a very large placed image decoded to RGBA without a size limit in image::decode) look the same, although after a trap the WASM instance is unusable: every later command fails, autosave throws on engine.save(), and the user keeps working on edits that are no longer kept.

Treat WebAssembly.RuntimeError apart: stop autosave and show the start-failure notice with a reload button (the last autosave is intact); refuse images above a pixel limit in add_image with a message.

TEST-5low

Vitest depends on artefacts written by cargo test and wasm-pack

engine/src/display_list.rs test writing web/src/testdata/; web/src/displayList.test.ts; web/src/renderer.test.ts; .gitignore

A Rust test writes display-list.bin/.json into the gitignored web/src/testdata, which the TS decoder test reads; renderer.test.ts needs the wasm-pack output. ./check runs them in the right order, but pnpm test on a fresh clone fails with a missing file, and a test with a side effect on another package is surprising.

Commit the fixture and let the Rust test compare against it (failing with a hint to regenerate), so both sides check the same file; state in the README that pnpm test needs the wasm build.

TEST-1low

E2E runs Chromium only; layer reordering, File System Access and Local Font Access are untested

web/playwright.config.ts, web/e2e/, web/src/file.ts

Only Chromium (SwiftShader) runs, although Firefox is a settled target browser. No test in layers.spec.ts drags a layer to reorder it or into a group. file.spec.ts removes the file pickers and so tests saving and opening the way Firefox does; saving into the same file with showSaveFilePicker, the stored handle after a reload, and finding missing fonts with queryLocalFonts run in no test.

Add a layers drag-and-drop test (reorder, into a group); stub the pickers and queryLocalFonts with handles whose structured clone IndexedDB accepts; add a Firefox project once its WebGL path works in CI.

SEC-1low

GitHub Actions pinned to tags, not commits

.github/workflows/ci.yml

The deploy job holds pages: write and id-token: write; third-party actions (cachix/install-nix-action@v31 and the actions/* ones) are referenced by mutable major tags.

Pin actions to commit SHAs (Dependabot keeps them current).

BUILD-1info

Every build warns that the main chunk is over 500 kB

web/vite.config.ts

index-*.js is 535 kB (167 kB gzip), so pnpm build prints the chunk size warning on every run. Next to 14 MB of WASM it costs little, but a warning that is always there hides a new one.

Set build.chunkSizeWarningLimit just above the current size, so growth still warns.
